# Android Review Skill 详细使用说明书

## 概述

Android Review Skill 是一个专业的 Android/Kotlin 代码审查工具，专为 Android 开发者设计，用于自动检测代码质量、最佳实践遵循情况和潜在问题。该工具支持：

- **静态规则扫描**：基于正则表达式和语法分析检测代码问题
- **多领域规则支持**：协程、Compose、Flow、Hilt、Dagger2 等现代 Android 开发技术
- **LLM 语义增强**：可选地使用 AI 进行更深层次的代码理解和建议
- **报告生成**：JSON 和 HTML 格式的详细审查报告
- **GitHub Action 集成**：支持 CI/CD 流水线自动审查

## 系统要求

- Python 3.8+
- Git 2.20+
- 对于 LLM 功能：DeepSeek API Key 或 OpenAI API Key

## 快速开始

### 1. 安装依赖

```bash
cd review_skill
pip install -r requirements.txt
```

### 2. 基本使用

```bash
# 运行代码审查（默认使用当前 git diff）
python3 review.py

# 或者指定配置文件
python3 review.py --config custom_config.json
```

### 3. 查看结果

工具将输出：
1. JSON 格式的审查结果
2. HTML 可视化报告（默认开启）
3. 详细的分数和问题列表
4. 是否阻塞 PR 的判断

## 详细配置

### 配置文件结构

工具在 `review_skill/review_config.json` 中提供了详细的配置选项：

```json
{
  "file_extensions": [".kt", ".kts"],
  "scan_directories": [
    "app/src/main/java",
    "app/src/test/java",
    "app/src/androidTest/java"
  ],
  "exclude_patterns": [
    "*/build/*",
    "*/.gradle/*",
    "*/.idea/*",
    "*/.git/*",
    "*/debug/*"
  ],
  "enable_semantic_review": true,
  "generate_html_report": true,
  "min_score_threshold": 70,
  
  "rule_engine": {
    "use_new_engine": true,
    "new_engine_config": {
      "enabled_categories": ["security", "performance", "correctness", "concurrency", "lifecycle"],
      "disabled_rules": [],
      "parallel_execution": true,
      "cache_enabled": true,
      "max_workers": 4,
      "cache_ttl": 3600,
      "execution_timeout": 30
    }
  }
}
```

### 配置说明

#### 文件过滤配置
- **file_extensions**: 要扫描的文件扩展名列表（仅支持 Kotlin 文件）
- **scan_directories**: 要扫描的目录列表（相对于项目根目录）
- **exclude_patterns**: 要排除的文件/目录模式（支持 glob 语法）

#### 功能配置
- **enable_semantic_review**: 是否启用 LLM 语义分析
- **generate_html_report**: 是否生成 HTML 可视化报告
- **min_score_threshold**: 最小通过分数（低于此分数会阻塞 PR）

#### 规则引擎配置
- **use_new_engine**: 是否使用新的统一规则引擎
- **new_engine_config**: 新引擎的详细配置
  - **enabled_categories**: 启用的规则分类
  - **disabled_rules**: 禁用的具体规则 ID
  - **parallel_execution**: 是否并行执行规则
  - **cache_enabled**: 是否启用规则缓存
  - **max_workers**: 最大并行工作线程数

## 规则详解

### 规则分类

工具支持以下规则分类：

#### 1. 基础规则（Base Rules）
- **no_globalscope**: 禁止使用 `GlobalScope.launch`（生命周期不安全）
- **viewmodel_context**: ViewModel 不应持有 Android Context
- **main_thread_io**: 主线程上的 IO 操作检测

#### 2. 协程规则（Coroutine Rules）
- 协程生命周期管理
- 协程取消和异常处理
- 协程作用域管理

#### 3. Compose 规则（Compose Rules）
- 重组优化检测
- Compose 状态管理
- Compose 副作用管理

#### 4. Flow 规则（Flow Rules）
- Flow 生命周期管理
- Flow 异常处理
- Flow 转换优化

#### 5. Hilt/Dagger2 规则
- 依赖注入最佳实践
- 作用域管理
- 组件生命周期

#### 6. 代码结构规则
- 包结构组织
- 类和方法设计
- 代码复用性

### 规则严重程度

每个规则都有以下严重程度：

1. **blocker** (100分)：严重问题，必须修复
2. **critical** (20分)：关键问题，影响应用稳定性
3. **major** (10分)：主要问题，影响代码质量
4. **minor** (5分)：次要问题，建议修复
5. **info** (0分)：信息提示，不影响分数

### 分数计算规则

- 初始分数：100分
- 每个发现的问题根据严重程度扣分：
  - blocker: 扣100分（直接失败）
  - critical: 扣20分
  - major: 扣10分
  - minor: 扣5分
  - info: 不扣分
- 最终分数 = max(0, min(100, 100 - 总扣分))

## 使用场景

### 场景1：本地开发实时审查

```bash
# 在代码提交前运行审查
python3 review.py

# 输出示例：

# - HTML 报告链接
```

```bash

name: Code Review
on: [pull_request]
jobs:
  code-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Python
        uses: actions/setup-python@v4

          python-version: '3.9'
      - name: Install dependencies
        run: |
          pip install -r review_skill/requirements.txt
      - name: Run code review
        run: |
          cd review_skill
          python3 review.py
        env:
          DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}
```

## 高级功能

### 1. 规则引擎选择

工具支持两种规则引擎：

#### 旧引擎（Legacy Engine）
- 基于独立规则模块
- 简单的规则执行
- 适合简单场景

#### 新引擎（Enhanced Engine）
- 统一规则接口
- 并行规则执行
- 规则缓存优化
- 可扩展的规则注册机制
- 详细的统计信息

```python
# 手动使用新引擎
from rule_engine.integration.review_runner import ReviewRunner

runner = ReviewRunner(config)
runner.initialize()
results = runner.review_diff(git_diff_text)
```

### 2. 自定义规则开发

#### 创建新规则

```python
# 在 review_skill/rules/ 目录下创建新规则文件
# custom_rules.py

import re
from rule_engine.interfaces import Rule, RuleSeverity, RuleCategory

class MyCustomRule(Rule):
    def __init__(self):
        super().__init__(
            rule_id="my_custom_rule",
            name="我的自定义规则",
            description="检测特定模式",
            severity=RuleSeverity.MAJOR,
            category=RuleCategory.CORRECTNESS
        )
    
    def execute(self, context):
        findings = []
        if "bad_pattern" in context.code:
            findings.append(self.create_finding(
                message="发现不良模式",
                line_number=self._find_line_number(context.code, "bad_pattern")
            ))
        return findings
```

#### 注册规则

```python
from rule_engine.registry import RuleRegistry

registry = RuleRegistry()
registry.register(MyCustomRule())
```

## 故障排除

### 常见问题

#### 问题1: 未检测到任何代码变更

**可能原因**：
1. Git diff 为空
2. 配置文件过滤过于严格
3. 代码变更不在扫描目录中

**解决方案**：
```bash
# 检查 git diff
git diff HEAD~1..HEAD

# 检查配置文件
cat review_skill/review_config.json

# 临时放宽配置
export REVIEW_SCAN_DIRECTORIES="."
python3 review.py
```

#### 问题2: LLM 功能不可用

**可能原因**：
1. API 密钥未设置
2. 网络连接问题
3. API 配额不足

**解决方案**：
```bash
# 检查 API 密钥
echo $DEEPSEEK_API_KEY

# 测试 API 连接
python3 review_skill/test_deepseek_api.py

# 禁用 LLM 功能
export REVIEW_ENABLE_SEMANTIC="false"
```

#### 问题3: 规则引擎初始化失败

**可能原因**：
1. 依赖包缺失
2. Python 版本不兼容
3. 配置文件错误

**解决方案**：
```bash
# 重新安装依赖
pip install -r review_skill/requirements.txt --force-reinstall

# 使用旧引擎
export RULE_ENGINE_USE_NEW="false"

# 检查 Python 版本
python3 --version
```

### 调试模式

```bash
# 启用详细日志
export LOG_LEVEL="DEBUG"
python3 review.py

# 或者直接修改代码
import logging
logging.basicConfig(level=logging.DEBUG)
```

## 性能优化

### 1. 缓存策略

- **内存缓存**: 默认启用，适合小型项目
- **文件缓存**: 适合大型项目，减少重复计算
- **Redis缓存**: 适合分布式环境

### 2. 并行处理

- **max_workers**: 根据 CPU 核心数调整
- **执行超时**: 防止单个规则执行时间过长
- **资源限制**: 控制内存和 CPU 使用

### 3. 增量扫描

- 只扫描变更的文件
- 缓存规则执行结果
- 增量更新报告
